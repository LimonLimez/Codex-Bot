# Privacy

Open Bot is local-first. Private browser seats remain the default. Its services listen only on `127.0.0.1`, use fresh random local credentials, and store each bot's browser profile separately under the current Windows user's Local AppData folder.

The project does not collect telemetry. Operational logs stay on the PC. Browser and bridge diagnostics remove URL paths, credentials, queries and fragments, plus bearer tokens, API keys, JWTs, and device codes before writing. API keys entered in the app are protected with Windows DPAPI for the current user. CLIProxyAPI manages OAuth and imported provider credentials in this installation's private local state directory. A Vertex service-account upload is held in a private temporary file only for the local import and is then deleted; the resulting CLIProxy credential remains in that private auth directory.

If the user authorizes installation-time bootstrap, Setup downloads the separate Grok Bot 0.18.0 installer directly from `downloads.cursor.com`; that request is visible to the vendor host and is governed by the vendor's [privacy policy](https://cursor.com/privacy). The verified vendor app remains separately installed if Open Bot Setup is canceled, fails, or is later uninstalled.

Prompts, conversation context, and requested tool results - including page text or screenshots when the computer tool is used - are sent only to the AI route selected in Settings: OpenAI Codex, Anthropic Claude, Google Antigravity, Moonshot Kimi, xAI, Google Vertex AI, or a direct OpenAI API key. The patched app does not silently fall back to a different model provider. Each provider receives the data required to answer that request under its own account, terms, and privacy policy. Websites opened in a browser seat receive the normal data needed to use those sites.

Browser-originated HTTP(S) and WebSocket traffic is forced through authenticated per-seat proxies. The proxies reject any destination whose literal address or any DNS answer is local, private, link-local, reserved, or a cloud-metadata address, and pin each connection to the checked public address. Page WebRTC APIs, non-proxied WebRTC UDP, Chromium QUIC, page clipboard access, permission prompts, and automatic downloads are disabled. These application-layer controls do not replace the privacy policies or security practices of public sites.

The opt-in **Experimental vendor cloud computer** signs in separately to the vendor and reconnects to one persistent account box shared by all employees. The helper sends the authentication, access-check, provisioning, and primary remote-display traffic required to operate it. It does not intentionally send selected model-provider credentials, full prompts, or conversation history to the vendor control plane. Screen frames, pointer and keyboard input, text entered into the remote computer, public IP information, and the sites and accounts used inside that computer are necessarily processed by the vendor-managed environment and those sites.

Vendor OAuth credentials are stored separately under `%LOCALAPPDATA%\Open Bot\official-computer` and protected with current-user Windows DPAPI. Provisioning and display credentials are kept only in helper memory. If the Windows user enables the provider-only **Always allow computer actions** setting, that choice is also stored there under current-user DPAPI; it contains no vendor bearer token and is cleared by vendor sign-out or a new vendor sign-in. While enabled, mutating actions on the shared vendor computer do not show individual approval cards. The project itself does not collect telemetry, but the vendor-managed computer may contain vendor inference, telemetry, transcript, or other background services that this project cannot inspect or disable. Zero vendor inference, telemetry, or charges cannot be guaranteed, and billing is possible.

Never upload `%LOCALAPPDATA%\Open Bot`. It may contain model-provider and vendor-computer credentials, conversations, attachments, downloads, logs, browser cookies, browsing history, routines, and active login sessions. The repository's ignore rules and release audit block that state and common credential patterns.

The interactive uninstaller asks whether to preserve the state directory for a future reinstall or permanently wipe it. Choosing **No** at the wipe prompt preserves the directory, and silent uninstall always preserves it. Choosing **Yes** deletes conversations, OAuth state, downloads, settings, logs, routines, and signed-in browser profiles from this PC. Signing out of the experimental mode likewise removes its local vendor credentials and closes the view. These local operations cannot be undone by Open Bot, do not revoke every credential or session already stored by remote services, and do not verify deletion of the persistent vendor cloud computer or its data. There is no verified remote deletion receipt.
